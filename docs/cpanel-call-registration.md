# به‌روزرسانی ثبت تماس روی cPanel

این تغییر روی Python 3.12.14 آزمایش شده و وابستگی جدیدی ندارد.
تغییرات محیط توسعه به‌صورت خودکار روی هاست اعمال نمی‌شوند.

## نصب

1. در زمان مناسب، برنامه آزمایشی را در Python Selector متوقف کنید.
2. از فایل‌های قبلی و دیتابیس هاست نسخه پشتیبان بگیرید. برای دیتابیس SQLite
   می‌توانید در Execute python script فرمان `manage.py backup_db` را اجرا کنید؛
   موفقیت ساخت فایل بکاپ را نیز بررسی کنید.
3. فایل‌های اجرایی فهرست‌شده را در مسیر متناظر زیر
   `/home/digiran5/crm_digiran_test` جایگزین/اضافه کنید.
4. فایل‌های `.env`، `db.sqlite3`، `.htaccess` و فایل‌های `passenger_*.py`
   مخصوص هاست را حفظ کنید؛ دیتابیس محیط توسعه را آپلود نکنید.
5. از Execute python script، به‌ترتیب اجرا کنید:
   - `manage.py migrate --noinput`
   - `manage.py check`
6. پس از موفقیت، برنامه را Start/Restart کنید و مرورگر را تازه‌سازی کنید.

نیازی به تغییر Python Selector، نصب مجدد وابستگی‌ها یا بازسازی فایل‌های استاتیک نیست.

## بررسی رفتار

- نام خالی یا دارای عدد و شماره‌ای غیر از دقیقاً ۱۱ رقم، ثبت نشود؛ ارقام فارسی و عربی پذیرفته شوند.
- هدف و وضعیت انتخاب‌شده در تماس ذخیره شوند.
- ساعت تماس از زمان سرور هنگام ثبت ذخیره و در تاریخچه به وقت تهران نمایش داده شود.
- «قصد خرید دارد» برچسب بالقوه و «فاقد شرایط» برچسب سرنخ بدهد؛
  «قصد خرید دارد» پیگیری را الزامی می‌کند و نیازمند تاریخ معتبر است؛
  برای «فاقد شرایط»، پیگیری به‌صورت دستی قابل انتخاب است.
- انتخاب نیاز به پیگیری، ارسال آدرس را در فرم فعال کند و برداشتن تیک، آن را خاموش کند؛ ارسال آدرس بدون پیگیری
  نیز قابل انتخاب باشد. درخواست همراه ثبت موفق تماس پردازش می‌شود.
- پیامک فعلاً فقط آزمایشی است: درخواست در تماس ذخیره و در لاگ با عبارت
  `Address SMS requested (TEST ONLY; NOT SENT)` و شناسه مشتری ثبت می‌شود.
  شماره مشتری یا متن پیامک در این لاگ نوشته نمی‌شود و هیچ درخواست شبکه‌ای ارسال نمی‌شود.
- آخرین شرایط درخواستی تماس، فیلدهای خالی فرم پرونده را پیش‌پر می‌کند.
  انتخاب بازنشسته، شغل خالی را نیز پیش‌پر می‌کند. اطلاعات قبلی پرونده حفظ می‌شود؛
  تکمیل و ذخیره نهایی پرونده همچنان در مرحله خودش انجام می‌شود.
