# رفع غیرفعال ماندن فهرست‌های نتیجه مراجعه — نسخه ۵۴

در نسخه ۵۳، فیلدهای «دلیل کنسلی» و «ارجاع پیگیری به کارشناس فروش» ابتدا غیرفعال می‌شدند و Tom Select با همان وضعیت ساخته می‌شد. پس از انتخاب «منصرف شد»، ویژگی disabled فیلد اصلی برداشته می‌شد اما وضعیت داخلی و نمای ظاهری کنترل کشویی همچنان غیرفعال می‌ماند. این وضعیت در مرورگر بازتولید شد: هر دو فیلد `nativeDisabled=false` و `widgetDisabled=true` داشتند. آزمون قبلی مقدار را از API کنترل تنظیم می‌کرد و این ایراد کلیک واقعی را تشخیص نمی‌داد.

اکنون هم فیلد اصلی و هم کنترل نمایشی با API فعال/غیرفعال می‌شوند. تغییر وضعیت فقط روی ورودی‌های واقعی فرم اعمال می‌شود و ورودی جستجوی ساخته‌شده داخل کنترل دستکاری نمی‌شود. فیلدی که از ابتدا با تنظیمات سمت سرور غیرفعال بوده، فعال نمی‌شود. مجوز انتخاب مسئول و اعتبارسنجی سمت سرور همان قواعد نسخه ۵۳ را دارند.

بررسی مرورگر با کلیک واقعی در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ موفق بود: انتخاب دلیل و کارشناس، تغییر مکرر بین سه نتیجه، همگامی وضعیت کنترل و فیلد اصلی، حضور مقادیر در داده ارسالی و نبود خطای JavaScript یا بیرون‌زدگی افقی. ۱۲ آزمون نتیجه مراجعه نیز موفق بودند. ارتقا از نسخه ۵۳ و نصب دوباره با حفظ داده‌ها و بدون وظیفه، اعلان یا گزارش تکراری بررسی شد. migration جدیدی لازم نیست.

برای نصب، فایل `scripts/update_customer_workflow_v54.py` را کنار `manage.py` بگذارید و با Python محیط مجازی اجرا کنید:

```sh
python update_customer_workflow_v54.py
```

پس از `SUCCESS` برنامه را Restart کنید. نصب‌کننده تجمعی است و پشتیبان می‌گیرد. این نسخه روی هاست کاربر نصب نشده است.
