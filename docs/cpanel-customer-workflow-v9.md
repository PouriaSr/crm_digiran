# V9 — پیش‌فرض تحلیل مشتری و مجوزهای عملیات مرکز مشتریان

اسکریپت مستقل `scripts/update_customer_workflow_v9.py` را با **Download raw file** دانلود و کنار `manage.py` در `crm_digiran_test` آپلود کنید. در **Execute python script** اجرا کنید:

```text
update_customer_workflow_v9.py
```

پس از SUCCESS برنامه را Restart و مرورگر را Ctrl+F5 کنید. اسکریپت از کد و SQLite پشتیبان می‌گیرد، مهاجرت‌ها و بررسی‌ها را انجام می‌دهد و تنظیمات `.env`، Passenger و `.htaccess` را حفظ می‌کند. نسخه‌های قبلی لازم نیست. گزارش: `logs/workflow_v9_update.log`؛ پشتیبان: `backups/workflow-v9-*`.

## تحلیل مشتری

فرم هر بار با «فاقد شرایط» و برچسب «سرنخ» باز می‌شود. مقدار واقعی select، نمایش TomSelect و وضعیت Alpine با هم تنظیم می‌شوند؛ انتخاب «قصد خرید دارد»، برچسب «بالقوه» و رفتار پیگیری قبلی را فعال می‌کند. بازکردن دوباره فرم، وضعیت انتخاب قبلی را به فرم جدید منتقل نمی‌کند. تیک‌های اقدام بعدی مطابق همان پلن هستند.

## دسترسی‌ها

در **مدیریت کاربران → ویرایش → سطوح دسترسی پیشرفته**:

| قابلیت | مجوز |
| --- | --- |
| مشاهده تب‌ها | اطلاعات، پذیرش، پرونده، ثبت اطلاعات، استخدام و فاکتورها؛ کلیدهای قبلی |
| ثبت ورود پذیرش | `customers.reception_add` |
| ارجاع پذیرش و توقف تایمر | `customers.reception_refer` |
| ثبت/ویرایش پرونده | `customers.case_edit` |
| ثبت/ویرایش مرحله اطلاعات تکمیلی | `customers.registration_edit` |
| انتقال کارت مشتری | `customers.reassign` |
| افزودن، ویرایش، حذف و سنجاق یادداشت | `customers.notes_add` / `notes_edit` / `notes_delete` / `notes_pin` |
| ورود از Excel، قالب و پیش‌نمایش | `customers.excel_import` |
| ویرایش اطلاعات مشتری | `customers.edit` |
| ثبت/ویرایش/انتقال تماس | `calls.add` / `calls.edit` / `calls.reassign` |
| ثبت پیگیری | `customers.followup` |
| اطلاعات شخصی کامل | `customers.profile_full` |

مجوز جدید در حالت «خودکار»، بازنویسی قدیمی مجوز پایه‌اش را رعایت می‌کند. مثلاً سلب قدیمی مجوز پذیرش، مجوز ثبت و ارجاع آن را خودکار باز نمی‌کند. برای یک تب فقط‌خواندنی، مشاهده تب را فعال و عملیات زیرمجموعه را سلب کنید. ستون «موثر» همین ارث‌بری را نشان می‌دهد. تغییرات هر کاربر در درخواست بعدی اعمال می‌شوند.

ویرایش مشتری و تماس علاوه بر مجوز، شرط **مسئول فعلی کارت / سرپرست / ادمین** دارد. نویسنده تماس، مالک کارت محسوب نمی‌شود. نقش‌های عادی می‌توانند ویرایش کارت خود را داشته باشند؛ سلب مجوز پیشرفته، همان دسترسی را هم مسدود می‌کند. اعطای ویرایش به فرد دیگر، مالکیت کارت را دور نمی‌زند. ثبت تماس و پیگیری همکار همچنان ممکن است؛ این عملیات، اطلاعات هویتی و شرح پروفایل را بدون مجوز ویرایش بازنویسی نمی‌کند.

انتقال معمول کارت و تماس همچنان به نقش سرپرست یا ادمین نیاز دارد؛ اعطای مجوز به اپراتور این شرط نقش را حذف نمی‌کند. سلب مجوز انتقال از سرپرست اعمال می‌شود. ارجاع پذیرش، عملیات جداگانه منشی است.

منشی به‌صورت پیش‌فرض تب اطلاعات و پذیرش، اپراتور تب اطلاعات، سرپرست همه تب‌های مرکز مشتریان و ادمین کل سیستم را دارد. ادمین سوپریوزر همیشه دسترسی کامل دارد. مجوز مشاهده با ویرایش مستقل است؛ سلب ویرایش، داده‌ها را حذف نمی‌کند. نمایش/ویرایش اطلاعات شخصی کامل به مجوز `customers.profile_full` وابسته است؛ فاکتورها به `invoices.view` وابسته‌اند.

دکمه‌ها و مسیرهای مستقیم سرور از همین مجوزها پیروی می‌کنند. ویرایش تماس در تاریخچه از ویرایش پروفایل مشتری مستقل شده است. عملیات یادداشت علاوه بر مجوز، همچنان به نویسنده یادداشت یا ادمین محدود است؛ ویرایش متن، سنجاق قبلی را ناخواسته تغییر نمی‌دهد. مسیرهای یادداشت برای اجرای پروژه زیر `/test` نیز اصلاح شده‌اند.
